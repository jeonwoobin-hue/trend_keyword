# UI_UX_Rules.md — 디자인 시스템 및 웹앱 개발 원칙

> 공통 규칙은 [../CLAUDE.md](../CLAUDE.md) 참고. 화면 목록/계층은 [../TrendFit-ux-docs/ia.md](../TrendFit-ux-docs/ia.md) 참고.

## 1. UI 원칙

- UI는 최대한 단순하게 만듭니다. 데이터 시각화 중심의 대시보드 UI를 지향합니다.
- 불필요한 애니메이션을 넣지 않습니다.
- 데스크톱/태블릿을 우선 지원하고, 모바일 웹은 최소 지원 수준으로 고려합니다(SRS §2.3).
- 반응형 레이아웃을 우선합니다.
- **사용자가 클릭 3번 안에 원하는 정보를 찾을 수 있도록 설계**합니다.

## 2. 정보 구조 가이드

- 새 화면/기능 추가 시, IA(`ia.md`)의 Depth 기준으로 홈 → 목적지까지의 클릭 경로가 3번을 넘는지 항상 검토합니다.
- 현재 IA는 각 탭(대시보드/리포트/알림/큐레이션/마이페이지)에서 Depth 2까지만 정의되어 있습니다. 새 화면을
  추가할 때 이 깊이를 넘기지 않도록 하고, 넘길 경우 네비게이션 구조나 진입 동선을 재설계합니다.
- IA/기능명세서와 다른 화면 구조로 가야 한다고 판단되면, 먼저 이유를 설명하고 사용자 확인 후 반영합니다
  ([CLAUDE.md](../CLAUDE.md) §6-1 참고).

## 3. 접근성 (NFR-UX-002)

- WCAG 2.1 AA 수준을 준수합니다 — 색 대비, 키보드 내비게이션, 스크린리더용 대체 텍스트(썸네일/차트 등).
- Word Cloud, Network Graph 같은 시각화 요소는 대체 텍스트나 데이터 테이블 형태의 보조 표현을 함께 고려합니다.

## 4. 성능 원칙 (UI 관련)

- 불필요한 렌더링을 줄입니다.
- 큰 데이터는 Pagination(페이지 번호) 또는 무한 스크롤(커서 기반, CURATE 계열)을 사용합니다.
- 동일한 연산/조회를 반복하지 않고 필요하면 캐싱합니다 (API/성능 공통 원칙은 [API_Design.md](API_Design.md) 참고).
- 최초 로딩은 3초 이내(NFR-UX-001)를 목표로 하며, 무거운 연산(리포트 생성 등)은 로딩 상태 표시 또는
  비동기 처리(`SERVER_004`)로 전환합니다.

## 5. 컴포넌트 재사용

- 새 UI를 만들기 전 `components/`에 유사한 컴포넌트가 있는지 먼저 확인합니다.
- 여러 페이지에서 2회 이상 반복되는 UI 패턴(키워드 카드, 게이지, 알림 배지 등)은 즉시 `components/`로 분리합니다.

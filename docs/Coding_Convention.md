# Coding_Convention.md — 코딩 스타일 및 에러 처리

> 공통 규칙은 [../CLAUDE.md](../CLAUDE.md) 참고.

## 1. 코드 스타일

- PEP8 준수
- 타입 힌트 사용
- Docstring 작성 (함수의 목적, 인자, 반환값)
- 함수 길이 **50줄 이하** 권장 — 초과 시 하위 함수로 분리
- 클래스는 **단일 책임 원칙(SRP)** 준수
- 매직넘버 금지 → 상수는 `config/`에서 관리
- 상대경로 사용, 하드코딩 최소화
- 중복 코드 금지 (2회 이상 반복되면 함수/유틸로 분리)

## 2. 에러 처리

- `try-except`를 남용하지 않습니다. 실패할 수 있는 지점에서만 사용합니다.
- 에러를 잡기 전에 **에러 발생 원인을 먼저 확인**합니다 (원인 파악 없는 무분별한 except 금지).
- 사용자에게는 [API_Design.md](API_Design.md) §3 공통 에러 코드 표의 메시지를 사용합니다.
- 로그에는 상세 원인(스택트레이스, 요청 컨텍스트)을 남깁니다.
- 발생할 수 없는 상황에 대한 방어 코드는 추가하지 않습니다 (내부 호출 계약 신뢰, 시스템 경계에서만 입력 검증).

## 3. 테스트

- 새 기능은 가능하면 테스트 코드도 작성합니다 (pytest).
- 기존 기능이 깨지지 않는지 확인합니다 (변경 시 관련 테스트 우선 실행).
- 테스트 코드는 `tests/`에 소스와 동일한 폴더 구조로 배치합니다.
- 배치 잡(`worker/jobs`)은 **동일 입력을 여러 번 실행해도 결과가 같은지**(idempotency)를 테스트에 포함합니다.

## 4. 성능

- 동일한 연산은 반복하지 않습니다. 필요하면 캐싱합니다.
- API 호출을 최소화합니다 (상세는 [API_Design.md](API_Design.md) 참고).
- 큰 데이터는 Pagination 또는 Lazy Loading을 사용합니다.

## 4-1. Streamlit 관례 (프론트엔드)

- 데이터 로딩/외부 API 호출 함수는 `@st.cache_data`, 리소스(모델/커넥션)는 `@st.cache_resource`로 캐싱합니다.
- 화면 상태는 `st.session_state`로 관리하고, 페이지 간 공유가 필요한 로직은 `app/`의 공용 모듈로 분리합니다.
- 페이지(`pages/*.py`) 파일에는 UI 배치만 두고, 실제 계산/조회는 `services/`, `utils/`를 호출하는 형태로 얇게 유지합니다.
- Streamlit 위젯 `key`는 하드코딩 문자열 대신 `config/`에 정의된 상수를 사용해 페이지 간 중복/충돌을 방지합니다.

## 4-2. FastAPI 관례 (백엔드)

- 라우터(`api/routers/*.py`)는 요청 검증(Pydantic)과 응답 조립만 담당하고, 로직은 `services/`에 위임합니다.
- 요청/응답 모델은 `models/`에 정의하고 라우터·서비스가 함께 재사용합니다.
- 응답 포맷/에러코드는 [API_Design.md](API_Design.md) §2~3을 그대로 따릅니다.

## 4-3. 배치 워커 관례

- 각 잡(`worker/jobs/*.py`)은 실패 시 관리자 알림을 발송하고, 동일 잡의 중복 실행을 방지하는 락을 둡니다
  (functional-spec.md FR-DASH-003 예외처리 "배치 중복 실행" 참고).
- 잡 자체는 스케줄 트리거 역할만 하고, 계산 로직은 `services/`에 둬 API에서도 재사용 가능하게 합니다.

## 5. 리뷰 체크리스트

- [ ] 함수가 하나의 역할만 수행하는가
- [ ] 매직넘버 없이 `config/` 상수를 사용했는가
- [ ] 중복 로직이 없는가
- [ ] 타입 힌트와 docstring이 있는가
- [ ] 에러 발생 시 사용자 메시지(공통 에러코드)와 로그가 분리되어 있는가
- [ ] 배치 잡이라면 idempotent하고 중복 실행 방지 처리가 있는가

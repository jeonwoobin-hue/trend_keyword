# Data_Rules.md — 데이터 수집/분석 규칙

> 공통 규칙은 [../CLAUDE.md](../CLAUDE.md) 참고. 데이터 저장 위치는 [Architecture.md](Architecture.md) 참고.

## 1. 기본 원칙

- **데이터 없는 내용은 추측하지 않습니다.** 공식 문서/실제 호출로 확인되지 않은 지표 산정식은 "미정"이라고
  명시하고, 구현 시 확정되면 [KPI_Definitions.md](KPI_Definitions.md)를 갱신합니다.
- 모든 분석 전, 아래 4가지를 반드시 먼저 확인합니다.

## 2. 분석 전 필수 확인 항목

1. **결측치 확인** — 컬럼별 결측 비율, 결측 패턴(무작위 vs 특정 조건). 예: 표준편차 0으로 Spike Score
   계산이 불가능한 키워드는 결측이 아니라 0으로 정상 처리(§ [KPI_Definitions.md](KPI_Definitions.md) 참고)
2. **중복 데이터 확인** — 동일 키워드/기간 중복 수집 여부, 중복 제거 기준
3. **이상치 확인** — 통계적 이상치(IQR, z-score 등) 및 도메인상 비정상 값 (예: 언급량 급증이 실제 트렌드인지
   봇/어뷰징에 의한 왜곡인지)
4. **데이터 최신성 확인** — 수집/갱신 일자. 대시보드는 NFR-PERF-002(1시간 이내 반영) 기준을 만족하는지 확인

## 3. 분석 프로세스

1. **EDA(탐색적 데이터 분석) 결과를 먼저 제공**합니다. 결론보다 데이터 현황이 먼저입니다.
2. **분석 과정도 함께 제공**합니다 — 최종 수치만이 아니라 어떤 방법으로 도출했는지 설명합니다.
3. 결측치/중복/이상치 처리 방식을 결정했다면 그 근거를 명시합니다.

## 4. 원본 데이터 보호

- `data/raw/`(외부 API 원본 수집 스냅샷)는 절대 직접 수정하지 않습니다.
- 전처리는 항상 `data/raw/` → `data/processed/`로 새 파일을 생성하는 방식으로 수행합니다.
- 전처리 스크립트(배치 잡 포함)는 재실행 가능(idempotent)해야 합니다 — 동일 입력으로 여러 번 실행해도
  결과가 같아야 하며, 중복 실행 방지 락은 [Coding_Convention.md](Coding_Convention.md) 배치 관례 참고.

## 5. 개인정보 취급

- 사용자 프로필(연령대/성별/이메일 등)은 NFR-SEC-001(AES-256 저장)·NFR-SEC-002(TLS 통신) 요구사항을
  따릅니다. 로그·에러 메시지에 이메일 등 개인정보를 평문으로 남기지 않습니다.
- 관심도 가중치 보정(FR-DASH-005) 등 인구통계 기반 분석은 집계 수준에서만 사용하고, 개인 식별이
  가능한 형태로 노출하지 않습니다.

## 6. KPI와의 연결

반복적으로 사용하는 지표(Spike Score, 감성분석 비율 등)는 임의로 재정의하지 말고
[KPI_Definitions.md](KPI_Definitions.md)에 정의된 기준을 따릅니다.

## FR-ONBOARD-001 관심 분야·조건 설정

**관련 화면**: ONBOARD-001, ONBOARD-002
**우선순위**: [P1]
**관련 요구사항**: FR-ONBOARD-001, FR-ONBOARD-002, FR-ONBOARD-003

### 개요
> 사용자가 관심 분야, 목적, 연령대/성별, 선호 플랫폼, 탐색 기간을 입력해 맞춤 관심사 프로필을 생성한다.

### 트리거
- 회원가입 완료 후 최초 진입 시
- 마이페이지에서 [관심사 수정]을 탭했을 때

### 입력값
| 파라미터 | 타입 | 필수 | 유효성 검사 |
|----------|------|------|-------------|
| interests | array[string] | Y | 사전 정의 분야(패션/IT테크/여행/재테크/뷰티 등) 중 1~5개 |
| purpose | string | Y | enum: content_planning, purchase, market_research, casual |
| ageGroup | string | Y | enum: 10s, 20s, 30s, 40s, 50s, 60plus |
| gender | string | N | enum: male, female, unspecified |
| platforms | array[string] | Y | enum: youtube, instagram, news, x, gallery 중 1개 이상 |
| period | string | Y | enum: 24h, 1w, 1m |

### 처리 로직
1. 클라이언트: 각 항목 선택 여부 검증, 필수 항목 미선택 시 [다음] 버튼 비활성화
2. [다음] 탭 시 `POST /api/v1/profile/interests` 호출
3. 서버: 입력값 enum·개수 유효성 검사
4. 서버: 사용자 관심사 프로필 저장(upsert)
5. 서버: 저장된 조건 기반 추천 키워드 상위 5개 사전 산출(캐시 워밍)
6. 클라이언트: ONBOARD-002로 이동, 선택 요약 및 추천 키워드 미리보기 표시
7. [대시보드로 이동] 탭 시 DASH-001로 이동

### 출력/결과
- 성공 시: `{ "success": true, "data": { "profileId": 1, "previewKeywords": ["...", "..."] } }`
- 실패 시: 에러 코드 + 메시지

### 예외 처리
| 예외 상황 | 에러 코드 | 사용자 메시지 |
|-----------|-----------|---------------|
| 관심 분야 미선택 | VALID_001 | "관심 분야를 1개 이상 선택해주세요." |
| 선호 플랫폼 미선택 | VALID_001 | "선호 플랫폼을 1개 이상 선택해주세요." |
| 잘못된 값 전달 | VALID_002 | "요청 값이 올바르지 않습니다." |
| 네트워크 오류 | SERVER_001 | "네트워크 오류가 발생했습니다. 다시 시도해주세요." |

### API 엔드포인트 (안)
```
POST /api/v1/profile/interests
Request:  { "interests": ["fashion","beauty"], "purpose": "content_planning", "ageGroup": "20s", "gender": "female", "platforms": ["instagram","youtube"], "period": "1w" }
Response: { "success": true, "data": { "profileId": 1, "previewKeywords": ["...", "..."] } }
```

### Use Case 시나리오
**정상 시나리오:**
1. 사용자가 관심 분야, 목적, 연령대/성별, 플랫폼, 기간 입력
2. [다음] 탭 → 저장 완료 → 요약 화면에서 추천 키워드 확인
3. [대시보드로 이동] 탭 → DASH-001 진입

**예외 시나리오 A (필수값 미입력):**
1. 관심 분야 미선택 상태로 [다음] 탭
2. 선택 영역 하단에 인라인 에러 표시, API 미호출

**예외 시나리오 B (네트워크 오류):**
1. 오프라인 상태에서 저장 시도
2. 토스트 메시지 + 재시도 버튼 표시

## FR-DASH-001 트렌드 대시보드 조회

**관련 화면**: DASH-001
**우선순위**: [P1]
**관련 요구사항**: FR-DASH-001, FR-DASH-002, FR-DASH-006

### 개요
> 사용자의 관심사 프로필 조건에 맞는 분야별 핫 키워드와 언급량 그래프를 조회한다.

### 트리거
- 로그인 후 대시보드 탭 진입 시
- 분야·기간 필터 변경 시

### 입력값
| 파라미터 | 타입 | 필수 | 유효성 검사 |
|----------|------|------|-------------|
| category | string | N | 미지정 시 프로필의 관심 분야 전체 적용 |
| period | string | N | enum: 24h, 1w, 1m (기본값: 프로필 설정값) |
| page | integer | N | 1 이상 정수, 기본값 1 |

### 처리 로직
1. 클라이언트: 대시보드 진입 시 `GET /api/v1/dashboard/keywords` 호출
2. 서버: 사용자 관심사 프로필 조회, category 미지정 시 전체 관심 분야 적용
3. 서버: 캐시된 최신 집계 데이터(최대 1시간 이내 갱신분) 조회
4. 서버: 언급량·Spike Score 기준 정렬 후 상위 20개 반환
5. 클라이언트: 키워드 카드 리스트 + 언급량 그래프 렌더링
6. 필터 변경 시 2번부터 재수행

### 출력/결과
- 성공 시: `{ "success": true, "data": { "keywords": [{ "keyword": "...", "category": "...", "mentionCount": 12000, "spikeScore": 87.5, "trendGraph": [...] }] }, "meta": { "period": "1w", "updatedAt": "..." } }`
- 실패 시: 에러 코드 + 메시지

### 예외 처리
| 예외 상황 | 에러 코드 | 사용자 메시지 |
|-----------|-----------|---------------|
| 관심 분야 데이터 없음 | RES_001 | "표시할 트렌드 데이터가 없습니다." |
| 잘못된 기간 파라미터 | VALID_002 | "요청한 기간 값이 올바르지 않습니다." |
| 외부 데이터 지연/장애 | SERVER_002 | "일부 데이터가 최신이 아닐 수 있습니다." (캐시 데이터 + "갱신 지연" 배지) |
| 네트워크 오류 | SERVER_001 | "네트워크 오류가 발생했습니다. 다시 시도해주세요." |

### API 엔드포인트 (안)
```
GET /api/v1/dashboard/keywords?category=fashion&period=1w
Response: { "success": true, "data": { "keywords": [{ "keyword": "...", "mentionCount": 12000, "spikeScore": 87.5, "trendGraph": [...] }] }, "meta": { "period": "1w", "updatedAt": "2026-08-08T09:00:00Z" } }
```

### Use Case 시나리오
**정상 시나리오:**
1. 사용자 로그인 → 대시보드 진입
2. 관심 분야 핫 키워드 및 언급량 그래프 확인
3. 기간 필터를 1개월로 변경 → 갱신된 데이터 확인

**예외 시나리오 A (데이터 없음):**
1. 최근 추가된 분야 선택 시 데이터 부족
2. 빈 상태 메시지 + 다른 분야 추천 표시

**예외 시나리오 B (외부 API 장애):**
1. 외부 데이터 소스 응답 지연
2. 캐시 데이터에 "갱신 지연" 배지 표시 후 정상 노출

## FR-DASH-003 Spike Score(급상승 지수) 산출

**관련 화면**: DASH-001, DASH-002 (결과 노출), ADMIN-001 (모니터링)
**우선순위**: [P1]
**관련 요구사항**: FR-DASH-003

### 개요
> 키워드의 검색량·언급량이 평상시 대비 급증한 정도를 지수화하여 랭킹 및 알림에 활용한다.

### 트리거
- 배치 스케줄러가 매 시간 정각 자동 실행
- 관리자가 ADMIN-001에서 수동 재계산을 요청했을 때

### 입력값
| 파라미터 | 타입 | 필수 | 유효성 검사 |
|----------|------|------|-------------|
| targetDate | datetime | Y | 계산 기준 시각 |
| lookbackWindow | string | Y | enum: 7d, 30d (비교 기준 기간) |

### 처리 로직
1. 스케줄러가 시간당 1회 배치 작업 실행
2. 최근 수집된 키워드별 검색량·언급량 데이터 집계
3. 직전 lookbackWindow(기본 7일) 이동평균·표준편차 산출
4. Spike Score = (당일 언급량 − 이동평균) ÷ 표준편차를 0~100 스케일로 정규화
5. 표준편차 0, 데이터 누락 등 이상치는 필터링 후 결측 처리
6. 산출 결과를 키워드 집계 테이블에 저장, 대시보드 캐시 갱신
7. 임계치를 초과한 키워드는 알림 발송 대상 큐에 등록(FR-ALERT-003 연계)

### 출력/결과
- 성공 시: 배치 완료 로그 기록, 갱신된 키워드 수 반환
- 실패 시: 배치 실패 로그 기록 + 관리자 알림 발송

### 예외 처리
| 예외 상황 | 에러 코드 | 처리 방식 |
|-----------|-----------|---------------|
| 원본 데이터 수집 실패 | SERVER_003 | 관리자 알림 발송, 이전 캐시 유지 |
| 표준편차 0 | - | 해당 키워드 Spike Score 0 처리 (정상 처리, 에러 아님) |
| 배치 중복 실행 | VALID_003 | "이미 실행 중인 배치가 있습니다." 로그 후 스킵 |

### API 엔드포인트 (안)
```
POST /api/v1/admin/dashboard/recalculate-spike
Request:  { "targetDate": "2026-08-08T09:00:00Z", "lookbackWindow": "7d" }
Response: { "success": true, "data": { "updatedKeywords": 842, "failedKeywords": 3 } }
```

### Use Case 시나리오
**정상 시나리오:**
1. 매시간 배치 자동 실행 → Spike Score 갱신 → 대시보드/알림에 반영

**예외 시나리오 A (외부 API 장애로 데이터 누락):**
1. 해당 시간 배치 실패 → 이전 캐시 유지 + 관리자 알림

**예외 시나리오 B (관리자 수동 재계산):**
1. 이상 데이터 발견 시 관리자가 수동 재계산 요청 → 최신 결과 반영

## FR-DASH-004 키워드 상세(검색량 추이·감성분석) 조회

**관련 화면**: DASH-002
**우선순위**: [P1]
**관련 요구사항**: FR-DASH-004, FR-DASH-005

### 개요
> 특정 키워드의 검색량 추이, 긍·부정 감성 비율, 연관 키워드, 연령·성별 관심도를 상세 조회한다.

### 트리거
- DASH-001에서 키워드 카드를 탭했을 때

### 입력값
| 파라미터 | 타입 | 필수 | 유효성 검사 |
|----------|------|------|-------------|
| keywordId | string | Y | 존재하는 키워드 ID |
| period | string | N | enum: 24h, 1w, 1m (기본값: 프로필 설정값) |

### 처리 로직
1. 클라이언트: `GET /api/v1/dashboard/keywords/{keywordId}` 호출
2. 서버: keywordId 존재 여부 확인
3. 서버: 검색량 시계열, 감성분석 비율, 연관 키워드 Top 10, 연령·성별 가중치 보정 데이터 조회
4. 클라이언트: 추이 그래프 + 감성 비율 차트 + 연관 키워드 태그 렌더링
5. [알림 설정] 탭 시 ALERT-001로 이동(키워드 사전 입력)

### 출력/결과
- 성공 시: `{ "success": true, "data": { "keyword": "...", "trendSeries": [...], "sentiment": { "positive": 0.62, "negative": 0.18, "neutral": 0.20 }, "relatedKeywords": [...], "demographics": {...} } }`
- 실패 시: 에러 코드 + 메시지

### 예외 처리
| 예외 상황 | 에러 코드 | 사용자 메시지 |
|-----------|-----------|---------------|
| 존재하지 않는 키워드 ID | RES_001 | "해당 키워드 정보를 찾을 수 없습니다." |
| 감성분석 데이터 부족 | VALID_003 | "감성 분석을 위한 데이터가 충분하지 않습니다." (해당 영역 비활성) |
| 네트워크 오류 | SERVER_001 | "네트워크 오류가 발생했습니다. 다시 시도해주세요." |

### API 엔드포인트 (안)
```
GET /api/v1/dashboard/keywords/kw_001?period=1w
Response: { "success": true, "data": { "keyword": "...", "trendSeries": [...], "sentiment": {"positive":0.62,"negative":0.18,"neutral":0.20}, "relatedKeywords": ["..."], "demographics": {...} } }
```

### Use Case 시나리오
**정상 시나리오:**
1. 대시보드에서 키워드 탭 → 상세 화면에서 추이·감성분석 확인 → 관련 콘텐츠로 이동

**예외 시나리오 A (데이터 부족):**
1. 언급량이 적은 신규 키워드 탭 → 감성분석 영역 비활성 안내

**예외 시나리오 B (잘못된 접근):**
1. 삭제된 키워드 ID로 접근 → 404 안내 후 대시보드로 복귀

## FR-REPORT-001 인사이트 리포트 생성

**관련 화면**: REPORT-001, REPORT-002
**우선순위**: [P1]
**관련 요구사항**: FR-REPORT-001, FR-REPORT-002, FR-REPORT-003

### 개요
> 사용자가 선택한 조건(분야/기간)에 따라 최신 이슈 요약과 키워드 연관성 지도를 포함한 인사이트 리포트를 생성한다.

### 트리거
- REPORT-001에서 [리포트 생성] 버튼을 탭했을 때

### 입력값
| 파라미터 | 타입 | 필수 | 유효성 검사 |
|----------|------|------|-------------|
| category | string | Y | 사전 정의된 관심 분야 값 |
| period | string | Y | enum: 24h, 1w, 1m |
| title | string | N | 최대 50자 (미입력 시 자동 생성) |

### 처리 로직
1. 클라이언트: 조건 선택 후 `POST /api/v1/reports` 호출, 로딩 상태 표시
2. 서버: 조건에 맞는 키워드·이슈 데이터 집계
3. 서버: 주요 키워드·이벤트 기반 이슈 요약 텍스트 자동 생성
4. 서버: 키워드 동시 언급 빈도로 Word Cloud 가중치 및 Network Graph 노드·엣지 산출
5. 서버: 유사 관심사 그룹 데이터 비교로 추가 추천 키워드 도출
6. 서버: 리포트 저장(status: completed) 후 응답 반환
7. 클라이언트: REPORT-002로 이동하여 결과 렌더링

### 출력/결과
- 성공 시: `{ "success": true, "data": { "reportId": "rep_001", "summary": "...", "wordCloud": [...], "networkGraph": { "nodes": [...], "edges": [...] }, "recommendedKeywords": [...] } }`
- 실패 시: 에러 코드 + 메시지

### 예외 처리
| 예외 상황 | 에러 코드 | 사용자 메시지 |
|-----------|-----------|---------------|
| 데이터 부족으로 생성 불가 | RES_002 | "선택 조건에 대한 데이터가 부족하여 리포트를 생성할 수 없습니다." |
| 처리 시간 초과(대용량) | SERVER_004 | "리포트 생성이 지연되고 있습니다. 완료 시 알림으로 안내합니다." (비동기 전환) |
| 잘못된 기간/분야 값 | VALID_002 | "요청 값이 올바르지 않습니다." |

## FR-ALERT-001 급상승 알림 키워드 등록

**관련 화면**: ALERT-001
**우선순위**: [P1]
**관련 요구사항**: FR-ALERT-001, FR-ALERT-002

### 개요
> 사용자가 급상승 알림을 받을 키워드를 등록하고 알림 민감도(임계치)를 설정한다.

### 트리거
- ALERT-001에서 [키워드 추가]를 탭했을 때
- DASH-002에서 [알림 설정]을 탭했을 때

### 입력값
| 파라미터 | 타입 | 필수 | 유효성 검사 |
|----------|------|------|-------------|
| keyword | string | Y | 최대 50자, 사용자 기준 중복 불가 |
| thresholdScore | integer | N | 0~100, 기본값 70 |
| notifyChannel | array[string] | Y | enum: email, inapp 중 1개 이상 |

### 처리 로직
1. 클라이언트: 입력값 형식 검증(빈값, 중복 여부)
2. `POST /api/v1/alerts` 호출
3. 서버: 사용자당 최대 등록 키워드 수(20개) 초과 여부 확인
4. 서버: 알림 설정 저장
5. 클라이언트: 등록 리스트 갱신, 성공 토스트 표시

### 출력/결과
- 성공 시: `{ "success": true, "data": { "alertId": "alert_001", "keyword": "...", "thresholdScore": 75, "notifyChannel": ["email","inapp"] } }`
- 실패 시: 에러 코드 + 메시지

### 예외 처리
| 예외 상황 | 에러 코드 | 사용자 메시지 |
|-----------|-----------|---------------|
| 키워드 중복 등록 | VALID_003 | "이미 등록된 키워드입니다." |
| 최대 등록 개수 초과 | VALID_003 | "알림 키워드는 최대 20개까지 등록할 수 있습니다." |
| 수신 채널 미선택 | VALID_001 | "알림 수신 방식을 1개 이상 선택해주세요." |
| 네트워크 오류 | SERVER_001 | "네트워크 오류가 발생했습니다. 다시 시도해주세요." |

### API 엔드포인트 (안)
```
POST /api/v1/alerts
Request:  { "keyword": "...", "thresholdScore": 75, "notifyChannel": ["email","inapp"] }
Response: { "success": true, "data": { "alertId": "alert_001", "keyword": "...", "thresholdScore": 75, "notifyChannel": ["email","inapp"] } }
```

### Use Case 시나리오
**정상 시나리오:**
1. 사용자가 키워드 상세에서 [알림 설정] 탭 → 임계치 조정 → 등록 완료 토스트

**예외 시나리오 A (중복):**
1. 이미 등록된 키워드 재등록 시도 → 인라인 에러

**예외 시나리오 B (개수 초과):**
1. 21번째 키워드 등록 시도 → 토스트 안내

## FR-ALERT-003 급상승 알림 발송

**관련 화면**: ALERT-002 (결과 노출)
**우선순위**: [P1]
**관련 요구사항**: FR-ALERT-003

### 개요
> Spike Score 배치 결과가 사용자 설정 임계치를 초과하면 등록된 채널로 알림을 발송한다.

### 트리거
- FR-DASH-003 배치에서 임계치 초과 키워드가 큐잉된 직후, 알림 발송 워커가 자동 실행(시간당 1회)

### 입력값
| 파라미터 | 타입 | 필수 | 유효성 검사 |
|----------|------|------|-------------|
| alertQueue | array[object] | Y | { userId, keyword, spikeScore, thresholdScore, notifyChannel } 목록 |

### 처리 로직
1. 알림 발송 워커가 큐에 쌓인 대상 목록을 순회
2. 사용자별 동일 키워드의 최근 24시간 내 발송 이력 확인(재알림 최소 간격 6시간)
3. notifyChannel에 email 포함 시 이메일 발송 API 호출
4. notifyChannel에 inapp 포함 시 인앱 알림 테이블에 기록
5. 발송 결과를 알림 히스토리에 저장(성공/실패 상태 포함)
6. 사용자가 ALERT-002 진입 시 히스토리 목록으로 노출

### 출력/결과
- 성공 시: 발송 로그 기록, 인앱 알림 뱃지 갱신
- 실패 시: 발송 실패 로그 기록, 재시도 큐 등록(최대 3회)

### 예외 처리
| 예외 상황 | 에러 코드 | 처리 방식 |
|-----------|-----------|---------------|
| 이메일 발송 실패(SMTP 오류) | SERVER_005 | 최대 3회 재시도 후 실패 처리, 인앱 알림은 유지 |
| 동일 키워드 중복 발송(6시간 이내) | - | 발송 스킵, 로그만 기록 |
| 수신 채널 미설정 사용자 | VALID_001 | 발송 대상에서 제외, 로그 기록 |

### API 엔드포인트 (안)
```
GET /api/v1/alerts/history
Response: { "success": true, "data": { "alerts": [{ "keyword": "...", "spikeScore": 87.5, "sentAt": "...", "channel": "email", "status": "sent" }] }, "meta": { "page": 1, "total": 12 } }
```

### Use Case 시나리오
**정상 시나리오:**
1. 배치에서 임계치 초과 감지 → 이메일·인앱 알림 발송 → 사용자가 알림함에서 확인

**예외 시나리오 A (이메일 발송 실패):**
1. SMTP 오류로 발송 실패 → 재시도 큐 등록 → 3회 실패 시 인앱 알림만 유지

**예외 시나리오 B (중복 방지):**
1. 동일 키워드가 연속 시간대 계속 임계치 초과 → 6시간 내 재알림 스킵

## FR-CURATE-001 관련 콘텐츠 큐레이션 조회

**관련 화면**: CURATE-001, CURATE-002
**우선순위**: [P1]
**관련 요구사항**: FR-CURATE-001, FR-CURATE-002

### 개요
> 사용자의 관심 키워드와 연관된 인기 게시물·뉴스를 플랫폼별로 큐레이션하여 제공한다.

### 트리거
- 큐레이션 탭 진입 시, 무한 스크롤로 추가 로드 시
- 키워드 상세에서 [관련 콘텐츠 보기]를 탭했을 때

### 입력값
| 파라미터 | 타입 | 필수 | 유효성 검사 |
|----------|------|------|-------------|
| keyword | string | N | 특정 키워드 경유 진입 시 |
| platform | array[string] | N | enum: youtube, instagram, news, x (미지정 시 전체) |
| cursor | string | N | 페이징 커서 |

### 처리 로직
1. 클라이언트: `GET /api/v1/curations` 호출(필터 파라미터 포함)
2. 서버: keyword 또는 사용자 관심사 프로필 기준으로 연관 콘텐츠 조회
3. 서버: 플랫폼 필터 적용, 인기순 정렬(기본값)
4. 서버: 콘텐츠 메타데이터(썸네일, 제목, 출처, 발행일, 원문 링크) 반환
5. 클라이언트: 카드 리스트 렌더링, 스크롤 하단 도달 시 다음 커서로 추가 요청
6. 콘텐츠 카드 탭 시 CURATE-002 상세 이동 후 원문 링크 연결

### 출력/결과
- 성공 시: `{ "success": true, "data": { "contents": [{ "contentId": "c_1", "title": "...", "thumbnail": "...", "source": "YouTube", "platform": "youtube", "publishedAt": "...", "url": "..." }] }, "meta": { "nextCursor": "..." } }`
- 실패 시: 에러 코드 + 메시지

### 예외 처리
| 예외 상황 | 에러 코드 | 사용자 메시지 |
|-----------|-----------|---------------|
| 연관 콘텐츠 없음 | RES_001 | "관련 콘텐츠가 아직 없습니다." (다른 키워드 추천 노출) |
| 원문 링크 만료/삭제 | RES_003 | "원문을 찾을 수 없습니다." (카드 비활성 표시) |
| 잘못된 플랫폼 필터 값 | VALID_002 | "요청 값이 올바르지 않습니다." |
| 네트워크 오류 | SERVER_001 | "네트워크 오류가 발생했습니다. 다시 시도해주세요." |

### API 엔드포인트 (안)
```
GET /api/v1/curations?keyword=...&platform=youtube,instagram&cursor=abc123
Response: { "success": true, "data": { "contents": [{ "contentId": "c_1", "title": "...", "thumbnail": "...", "source": "YouTube", "platform": "youtube", "publishedAt": "2026-08-07T10:00:00Z", "url": "https://..." }] }, "meta": { "nextCursor": "abc124" } }
```

### Use Case 시나리오
**정상 시나리오:**
1. 사용자가 큐레이션 탭 진입 → 관심 키워드 관련 콘텐츠 스크롤 탐색
2. 관심 콘텐츠 탭 → 원문 이동

**예외 시나리오 A (콘텐츠 없음):**
1. 신규·희귀 키워드 조회 시 데이터 없음 → 빈 상태 안내

**예외 시나리오 B (원문 삭제):**
1. 삭제된 게시물 카드 탭 → "원문을 찾을 수 없습니다" 안내 표시
